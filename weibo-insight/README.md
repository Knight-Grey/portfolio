# 热搜是热搜，讨论是讨论

微博热搜话题的**讨论结构分析**作品页。纯静态、零依赖，双击 `index.html` 就能看。

- 用途：秋招作品集链接 + 课程作业展示
- 数据来源：隔壁 `..\weibo_hotsearch\` 采集器的产出
- 技术栈：原生 HTML / CSS / SVG（没有图表库、没有 CDN、没有构建）

---

## 一、目录结构

```
weibo_insight\
├── index.html          作品页（文案都在这里）
├── analyze.py          把采集结果整理成 data\data.js（只用标准库，不需要 pandas）
├── assets\
│   ├── style.css       样式（配色、排版、响应式）
│   └── app.js          手绘 SVG 图表（零依赖）
└── data\
    ├── data.js         页面实际读取的数据（analyze.py 生成）
    └── data.json       同样内容，方便你自己核对
```

---

## 二、怎么更新数据

**每次重新采集之后，跑一次：**

```powershell
cd F:\Desktop\测试项目\weibo_insight
python analyze.py
```

它会自动找到 `..\weibo_hotsearch\output\` 里**最新的一批** `top<N>_<时间戳>\` 目录，重新生成 `data\data.js`。

然后刷新 `index.html` 即可。不需要任何构建工具。

> `analyze.py` 只用标准库（`csv` / `json` / `glob` / `collections`），**不需要装 pandas**。

## 三、页面结构（七节）

| 节 | 标题 | 讲什么 |
|---|---|---|
| 01 | 榜上最热的话题，评论区未必最热 | **核心发现**：榜单热度占比 vs 实际评论占比 |
| 02 | 话题是有生命周期的 | 评论按时段铺开，看爆发与衰减形态 |
| 03 | 谁在带动讨论 | 博文点赞数 + 渠道类型（视频号 / 网页版） |
| 04 | 谁在说话：IP 属地 | 评论者的地域分布 |
| 05 | 情绪温度 | 各话题评论的正 / 中 / 负构成（词典规则打分） |
| 06 | 评论区里被顶起来的那些话 | 高赞评论卡片 |
| 07 | 方法与局限 | **主动交代**覆盖率、样本偏差、IP 与情感判定的局限 |

**第 07 节不要删。** 主动写局限，在答辩和面试里都是加分项——没有边界说明的舆情结论经不起追问。

### 情感是怎么判的

`sentiment.py` 是一个**可解释的规则打分器**，不是模型分类：

1. 在文本里找情感词（正向 / 负向，各带 1~3 的权重）
2. 看情感词前 4 个字里有没有否定词（不 / 没 / 别 / 无…）→ 权重取反
3. 看有没有程度副词（太 / 非常 / 有点…）→ 权重放大或缩小
4. 求和，`>= +1` 记正面，`<= -1` 记负面，其余中性

**已知失效场景**：反讽、反问句、词典未覆盖的领域词。
所以页面上**只呈现整体分布，不逐条引用**结论——这一点在「方法与局限」里也写明了。

想手动抽查某句话判得对不对：

```powershell
python sentiment.py "这是垄断吧，凭什么只能买一家" "我觉得挺合理的"
```

## 四、本地预览与部署

**本地**：直接双击 `index.html`。

> 为什么能双击打开？因为数据写在 `data/data.js` 里（`window.INSIGHT = {...}`），而不是用 `fetch` 读 JSON。浏览器在 `file://` 协议下会拦截 `fetch`，但 `<script src>` 不受影响。

**部署**（任选其一，都是拖拽即用）：

| 平台 | 操作 |
|---|---|
| Vercel | 新建项目 → 拖入 `weibo_insight` 文件夹 → 自动上线 |
| Netlify | 直接把这个文件夹拖进 [app.netlify.com/drop](https://app.netlify.com/drop) |
| GitHub Pages | 推到仓库 → Settings → Pages → 选根目录 |

整站只有 4 个文件，体积可以忽略。

## 五、要改的地方（重要）

1. **页脚署名**：`index.html` 最后的 `<footer>` 里现在是「数据采集与分析：自主编写」。换成你的名字和联系方式。
2. **首屏文案**：`<h1>` 和 `.lede` 是这份作品的「论点」，按你自己的话改一遍会更像你的作品。
3. **配色**：`assets/style.css` 顶部的 `:root` 变量，改 `--accent` 一个值就能换主色。

## 六、15 分钟讲解骨架

```
0-1min    为什么做这个：热搜是公共议题的入口，但榜单只有一个瞬时排名
1-3min    怎么抓的：三个接口、采集规模、覆盖率（一句话带过技术）
3-7min    发现一：榜单热度 ≠ 讨论量（第 01 节）
7-10min   发现二：账号类型决定议题能传多远（第 03 节）
10-13min  发现三：情绪温度——同一天里哪种议题最激愤（第 05 节）
13-15min  局限与下一步：覆盖率、样本偏差、IP ≠ 籍贯、词典判不出反讽
```

**重心在 3-13 分钟（10 分钟）。** 别把时间花在讲爬虫实现上——那是学生作业最常见的翻车方式。
